# 提案:統一的教學播放框架(Lesson Player)

狀態:**提案,待討論,尚未實作**。同意後才進入實作;同意的內容會併入 `docs/ic-spec.md`。
起因:試用回饋(動畫不夠動態、不知道看哪裡、目標是「只看不動手也能懂」)。

---

## 1. 為什麼要重新規劃:現在的做法是分裂的

| 面向 | 現況 | 問題 |
|---|---|---|
| 動畫的寫法 | 章節步驟是「程式碼一路播放」(`await tween…`);首頁是另一套(Web Animations);各畫面還有各自的累加計時 | 三種寫法;無法拖回去重看;無法在固定時間取樣 |
| 說明文字 | 每步一句固定文字 | 動畫播 10 秒,文字不變;看不出現在演到哪 |
| 「因」(輸入)在哪 | 側欄角落的核取方塊 | 因在畫面外、果在畫面內,視線被切開 |
| 視線引導 | 沒有 | 不知道看哪裡 |
| 降低動態 | 首頁、手繪抖動、設定各自處理 | 規則不一致 |
| 畫面上的疊層 | 「示意」標籤、圖例、圖內文字各自擺放 | 靠逐一測試避免重疊,沒有統一的版位 |

## 2. 設計目標(都來自你的回饋)
1. **只看不動手也能懂**:解釋完全由動畫與字幕承擔,互動只是加分。
2. **永遠知道看哪裡**:每一小段只有一個焦點,其餘變淡。
3. **因果被演出來**:輸入改變 → 開關動作 → 水流通過 → 輸出改變,中間不跳。
4. **可以重看**:拖回、重播這一小段、一小段一小段前進。
5. **一致**:所有章節與首頁用同一套寫法、同一組控制、同一個版位系統。

## 3. 名詞(文件、程式、畫面共用)
| 名詞 | 意思 | 畫面上叫 |
|---|---|---|
| 章 Lesson | 一個主題(如邏輯閘) | 章 |
| 步驟 Step | 一個概念(如反相器);有一句「必讀說明」 | 步驟 |
| **小段 Beat** | 步驟裡的一個瞬間:一句字幕、一個焦點、一組變化 | 小段(以圓點表示) |
| 時間表 Timeline | 一個步驟的全部小段,隨時間排列 | 時間軸 |
| 播放器 Player | 時間 → 畫面狀態的唯一來源 | — |
| 焦點 Focus | 此刻要看的東西(用框與箭頭標出) | 圈起來的地方 |
| 流動 Flow | 水/電流沿路徑的移動 | 紫色流動 |
| 模式 | **看**(自動播放)/**試**(自己操作) | 「自己試試」 |

## 4. 資料格式:步驟由「小段」組成(以反相器為例)
```js
{ id: 'inverter', level: 'core', label: {…}, say: '…必讀說明…', why: '…', uses: [],
  timeline: [
    { at: 0.0, caption: '反相器：輸出和輸入相反', focus: 'whole' },
    { at: 2.0, caption: '輸入是 0（低電壓）',       focus: 'input',  set: { a: 0 } },
    { at: 4.0, caption: '輸入同時控制上下兩個開關', focus: 'wires',  pulse: 'ctl' },
    { at: 6.0, caption: '上方接通，下方斷開',        focus: 'swUp',   tween: { upClosed: [0, 1, 0.5] } },
    { at: 8.0, caption: '高電壓流進輸出端的小水桶',  focus: 'bucket', flow: { up: [0, 1, 2.5] } },
    { at: 11.0, caption: '桶子滿了，輸出是 1',       focus: 'output', set: { y: 1 } },
    …
  ] }
```
- **宣告式**:時間表是資料,不是程式碼。播放器對任何時間 `t` 都能算出「此刻的參數、字幕、焦點」(純函式)。
- 因此**拖回、重播、取樣、單步、調速全部由同一個函式衍生**,不必各做一份。
- 每一小段的 `caption` ≤ 20 字、只講一件事;`focus` 必須是該畫面宣告過的目標。

## 5. 架構(沿用現有分層,只新增、不打散)
```
domain/timeline.js   純函式:軌道(set / tween / pulse / flow)、緩動、在時間 t 求值、小段索引
app/player.js        時鐘(播放/暫停/速度/拖曳)+ 目前狀態 + 事件;使用既有的排程器
render/…/views       畫面只實作 render(P):依參數畫圖;宣告可聚焦的目標 id 與可流動的路徑
ui/stage-layers.js   舞台疊層:字幕列、焦點框、小段圓點(同一個版位系統)
ui/timeline-bar.js   時間軸:拖曳、上一小段/下一小段、重播這一小段、速度
```
- 規則不變:`domain` 不碰 DOM,可在 Node 直接測;`check-deps` 持續把關。
- **移除**:`app/steps.js` 的「promise 步驟執行器」與章節裡的 `run(api)`(目前只有 5 個步驟要改寫)。
- **首頁動畫**:持續播放的主線動畫維持 Web Animations(省電、在合成器執行),但改成讀**同一種時間表資料**,並加上隨進度更換的字幕。兩種繪製、一份資料格式。

## 6. 舞台版位與統一的視覺語言
```
┌───────────────────────────────┐
│ [示意·非實際比例] [待審]  ← 左上:標籤(固定)│
│                               │
│        圖(焦點框在這裡移動)       │
│                               │
│ ● ● ○ ○ ○ ○   3/6             │  ← 小段圓點
│ ┌───────────────────────────┐ │
│ │ 字幕:上方接通，下方斷開      │ │  ← 底部字幕列(固定,隨小段更換)
│ └───────────────────────────┘ │
│ ◀ ▶ ———●—————  ⟲ 重播這段  1×  │  ← 時間軸
└───────────────────────────────┘
```
- 畫面保留給圖;標籤、字幕、焦點框各有固定位置,**不再逐一手動避開**。
- **「因」放進畫面**:輸入是畫面中的大開關,播放時看得到它被撥動;**側欄的核取方塊拿掉**。
- **模式**:預設「看」;按「自己試試」暫停時間表,畫面上的輸入開關變成可點擊,並出現本章的滑桿/開關。側欄的「步驟卡」只保留步驟摘要。
- **「先猜」也可以放進小段**:在關鍵小段暫停,問「輸出會是?」,選完再揭曉(沿用既有的獎勵,答錯不扣分)。

## 7. 動畫準則(所有章節與首頁共同遵守,寫進審查清單)
1. **每個動作都要有理由**:只畫會幫助理解因果的動作,不做純裝飾。
2. **先預告、再發生、再留下痕跡**:變化前有提示(脈衝/框),變化中有過程(擺動、流動),變化後有結果(亮起、數字)。
3. **一次只有一個焦點**;其餘降低對比。
4. **停留在變化完成之後**(≤ 0.8 秒),不要在變化發生前空等。
5. **數值一律「數字 + 顏色 + 粗細」同時表達**,不只靠顏色。
6. **流動是暫態**:只在「接通且水位未到」時流動,到了就停(這樣才不會教錯)。
7. **電流只畫流向**(沿用既有約定,不畫電子)。
8. **字幕不引入新名詞**(新名詞只在步驟必讀說明中第一次出現)。

## 8. 水桶與流動的規格(反相器、NAND)
- **輸出端畫成一個小水桶**:水位高 = 1、低 = 0;與基礎章「電壓像水位」同一套比喻。
- 上方開關接通:水從高電壓流向桶子,**桶子滿了才停**;下方開關接通:桶子的水排向低電壓,**排空才停**。
- NAND:並聯的上方只要有一條接通就能灌水;串聯的下方要**兩條都接通**才排得掉,流動的路徑把這一點演出來。
- 簡化聲明新增:「輸出端像水桶:實際是連線與下一級輸入的電容,教材先不談名詞」;「流動只畫暫態(充電、放電),穩定後不流,對應後續『靜止幾乎不耗電』」。**待審閱者確認這個畫法是否恰當。**

## 9. 降低動態與無障礙
- 「降低動態」:自動播放改為「一小段一小段」——每次按「下一小段」顯示該小段結束時的**靜態畫面**加字幕;沒有流動與擺動。
- 字幕為 `aria-live`;焦點框用**粗虛線加箭頭**,不只靠顏色;全部可用鍵盤(← → 換小段、空白鍵播放/暫停)。

## 10. 測試策略(換寫法後反而更好測)
- **單元測試**(純函式):時間表求值、緩動、小段索引、拖曳到任意時間的結果、重播、速度;「同一個 t 永遠得到同一個狀態」。
- **內容檢查**(`check-content`):字幕 ≤ 20 字;每個 `focus` 都是該畫面宣告的目標;每個 `set/tween/flow` 的參數都存在;時間遞增;最後一小段後有結論。
- **端對端**:在固定時間點取樣(取代現在的暫停加推進);檢查「該時間焦點框在哪、字幕是什麼、水桶水位」;降低動態的逐段模式;版位不重疊(統一版位後只需檢查一次)。
- 規則:任何視覺變更都要附**審查畫格**(沿用 `npm run review`)。

## 12. 風險與要先討論的事
| # | 疑慮 | 說明 | 我的建議 |
|---|---|---|---|
| 1 | **改動範圍** | 執行器、章節頁、畫面、內容、測試都會動 | 照階段走;S3 在分支上驗證,不滿意就丟棄,正式版不受影響 |
| 2 | **畫面變複雜** | 新增水桶、焦點框、字幕列、時間軸,零基礎的人可能更亂 | 每小段只強調一個東西;樣品後以試讀判斷;時間軸可收合 |
| 3 | **字幕與必讀說明重複** | 兩處都有文字 | 分工:字幕講「現在發生什麼」(≤ 20 字);必讀說明是整個步驟的摘要(≤ 40 字),放在側欄 |
| 4 | **「試」模式的位置** | 滑桿、輸入開關只在「自己試試」才出現 | 符合「只看也能懂」;基礎章的滑桿也移到「試」 |
