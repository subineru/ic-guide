## 3. 架構

```
content ──▶ domain ◀── app ◀── render / ui / audio
                ▲
              core
```

| 層 | 內容 | 規則 |
|---|---|---|
| `core` | 事件、儲存、雙語文字 | 不碰 DOM |
| `domain` | 課程圖、進度模型、**模擬模型**(歐姆、MOSFET、二進位、邏輯閘、移位暫存器、DAC、伽瑪、面板掃描) | 不碰 DOM/WebGL,可在 Node 直接 import 測試 |
| `content` | 各章資料(文字、步驟、參數、互動、檢核、查證欄位)、術語表、來源 | 以資料為主,以字串 id 引用 domain 模型與 render 視圖;**每章為獨立檔案,動態載入** |
| `app` | 步驟執行器(`api`)、排程器、路由、設定、進度服務 | 只用 core/domain |
| `render` | `r2d`(SVG)、`r3d`(three.js,動態載入);視圖實作 `create(ctx) → {update(state), dispose()}` | 不含課程文字 |
| `ui` | 外殼、心智圖首頁、學習面板、步驟清單、控制、設定 | 不含模擬邏輯 |
| `audio` | 合成器與互動音效 | 以事件觸發 |

### 模組與相依
- 一律原生 **ES modules**(`import/export`);**不使用全域變數**,不使用 `window.CF`。
- `check-deps.mjs` 解析 `import`(含動態 `import()` 的字面路徑),依上圖檢查層級,違規即失敗。
- `core/domain/content` 不得引用 `window/document`(用 ESLint 規則與檢查腳本雙重把關)。
- 所有資源路徑一律**相對路徑**(GitHub Pages 專案網址在 `/倉庫名/` 子路徑下)。

### 建置與部署
| 情境 | 作法 |
|---|---|
| 開發 | 不需建置;用 `http-server` 直接伺服 `src`(ES modules 需經 http) |
| 正式 | `esbuild`:打包、壓縮、依動態 import 拆分、檔名加雜湊,輸出 `dist/` |
| 部署 | GitHub Actions:跑檢查與測試,通過才部署到 GitHub Pages |
| 選配 | 同一份原始碼輸出**單檔離線版**(不拆分、內嵌),供倉庫建好前交付與離線雙擊開啟 |

取捨:多了 Node 工具鏈。**esbuild 是否能在本環境安裝尚未確認**,M0 第一步先驗證;備案是不壓縮的原生 ES modules 直接部署(可運作,只是檔案較大、較多)。

## 4. 資料模型(為「之後加更基礎的章節、重新編排」而設)

### 4.1 課程圖
`domain/curriculum.js` 是單一來源:每個節點 `{id, stage, needs:[章節 id], spine?}`,**章節順序由 `needs` 拓撲排序加一份人工 `ORDER` 清單決定**。新增基礎章節 = 新增節點並讓既有章節 `needs` 它;重新編排 = 改 `ORDER`。程式不改。

### 4.2 步驟與章節
- **id 一律有意義**(例:`water-analogy`),**不用 `s1、s2`**;id 一旦使用就不重用,語意改變就換新 id(由 `check-content` 比對上一版 id 清單把關)。
- 每個步驟標 `level`:`core` | `ext` | `deferred`。
  - `core`:計入完成與進度。
  - `ext`:選修,完成得金墨。
  - `deferred`:保留在資料檔,不顯示、不計入;**之後要擴充時啟用**。
- 每個章節宣告 `introduces: [術語 id]`(定義處)。`check-content` 依**目前路徑順序**驗證「先定義後使用」,重新編排後自動重驗。

### 4.3 進度
儲存格式 `{v:2, figs:{<章節id>:{steps:{<步驟id>:時間}, takeaways, ink}}}`;有版本欄位與遷移函式。新增章節不影響既有進度;已移除或改名的 id 在遷移時保留不報錯。

### 4.4 學習軌道
同一份內容、用 `level` 做視圖:**入門**(只顯示 core)與**完整**(core + ext)。切換畫面**現在不做**,只在資料模型留好欄位(避免過度設計)。

## 6. 教學設計

### 6.1 每章流程
1. **為什麼**:一句問題,連到主線。
2. **先猜**(選填、不計分):2~3 個選項;一律有獎勵(§6.5),答錯不扣分,只在說明中指出常見誤解。
3. **看**:4~7 個**核心步驟**(另有 ≤ 4 個選修**延伸步驟**);每步只講一個概念。
4. **做**:至少一個可操作元件;動畫一律可**暫停、單步、調速**(0.25×~2×,預設偏慢)。
5. **懂**:3 條「我能…」勾選;完成 = 核心步驟全部播完且全部勾選。
6. **接**:一句話銜接下一章,並在主線上標出位置。

### 6.2 驗收標準(`check-content` 自動檢查其中可量化者)
| 項目 | 標準 |
|---|---|
| 一步一概念 | 必讀說明 ≤ 40 字,只引入一個新名詞;「為什麼?」展開 ≤ 60 字 |
| 新名詞預算 | 每章**核心新名詞 ≤ 5**;延伸的名詞在延伸內自行定義 |
| 先定義後使用 | 依路徑順序檢查;核心步驟不得使用只在延伸中定義的術語 |
| 中英並列 | 每個術語有中文與英文 |
| 完整性 | 每章回答:**是什麼 / 為什麼需要 / 怎麼運作 / 常見誤解 / 簡化了什麼**;後三者放展開層 |
| 精確性 | 比喻只作入口,同時標示比喻的**限度** |
| 數字 | 未查證者一律標「示意」 |
| 份量 | 核心 5~8 分鐘、至少 1 個互動、3 條理解重點;延伸每章 ≤ 4 步 |

### 6.3 首頁:主線心智圖
- **脊椎**(橫向,資料流向):`[IC 外] 介面傳輸` → **驅動 IC 內:1 介面接收 → 2 移位暫存器 → 3 鎖存 → 4 位準轉換 → 5 數位轉類比(DAC)→ 6 緩衝器** → `[IC 外] 面板`。
  - **只有 IC 內的 6 個零件編號 1~6**;兩端不編號,改標「IC 外」,並以虛線框表示。IC 內的 6 個零件被一個「驅動 IC」方框包住。
  - 「位準轉換」的全名是「電壓位準轉換(level shifter)」,地圖與主線列用簡稱,避免與電源端的升壓電路混淆。
- **分支**(往下,「由什麼組成/要先懂什麼」):對應章節;**延伸步驟是葉子**。
- 另設「晶片本身」分支群:晶粒層疊、製程、封裝。
- **兩種關係分開畫**:流向用粗箭頭,組成/先修用細線,不混在一起。
- 排版為**手工固定座標的 SVG**(約 25 個節點),不用力導向排版,求整齊可預測。
- 獎勵疊在圖上:完成的章節讓節點上色;零件卡解鎖 = 節點亮起。
- 首頁含約 60~90 秒的**總覽動畫**:一個像素亮起的黑盒子,先讓人知道目的地。
- 章節內只顯示脊椎的**細流程條**,標出目前位置。手機上收合為細線。
- 備案:若試讀發現心智圖令人迷惑,退回只用細流程條。

### 6.4 概念相依
```
電 → 半導體(可被控制)→ 電晶體(開關)→ 0/1 與二進位 → 邏輯閘 → 正反器 → 移位暫存器 ─┐
晶粒層疊(結構觀)──────────────────────────────────────────────────────────────┤
面板掃描(列與行)────────────────────────────────────────────────────────────┼→ 資料到像素
灰階 = 位元;電阻分壓 → DAC → 伽瑪 ───────────────────────────────────────────────┘
製程(怎麼做出來)→ 封裝(裝到螢幕上)
```

### 6.5 獎勵機制(只加分,沒有失敗狀態)
- **墨滴**:完成步驟、勾選理解重點、做先猜(無論對錯)都得;猜對多一滴「金墨」;完成延伸步驟也得金墨。
- **零件卡**:每章完成解鎖一張手繪零件卡(背面有冷知識),集滿拼成「像素亮起」的完整畫;同時讓心智圖節點上色。
- 原則:不扣分、不倒退、無連續登入壓力、不設限時;獎勵動畫 ≤ 1 秒,只在完成時出現;可在設定關閉動畫與音效。
- 入門測驗:第一章開頭 3 題「先猜」;已懂的人答對後可選擇跳過,仍得墨滴。

## 7. 課程(建議路徑,可自由跳讀;未完成的先修只提醒、不阻擋)

路徑順序(章節 id):`basics → die → mosfet → digital → gates → scan → datapath → fab → package`
顯示序號依路徑自動產生。順序依工程師建議(由下而上),並在 `mosfet` 之後插入 `digital`,因為「開關通斷」自然引出 0/1。

| 章 id | 標題 | 呈現 | 核心新名詞(預算 ≤5) |
|---|---|---|---|
| `basics` | 電與半導體 Electricity & semiconductors | 2D | 電壓、電流、電阻、半導體 |
| `die` | 晶粒的層疊 Die layers | **3D** | 基板、電晶體層、配線層、連接孔、接點 |
| `mosfet` | 電晶體 Transistor | 2D | 閘極/源極/汲極、通道、CMOS |
| `digital` | 數位與二進位 Digital & binary | 2D | 位元、二進位、數位/類比、灰階 |
| `gates` | 邏輯閘到移位暫存器 Gates → shift register | 2D | 反相器、NAND、正反器、時脈、移位暫存器 |
| `scan` | 面板如何掃描 Scanning a panel | 2D | 列驅動、資料驅動、畫面、更新率 |
| `datapath` | 從資料到像素 Data to pixel | 2D | 介面、鎖存、電壓位準轉換、DAC、緩衝器(伽瑪移到延伸) |
| `fab` | 製程與設計分工 Fabrication | 2D | 光罩、光刻、蝕刻、摻雜、沉積(+fabless 分工) |
| `package` | 封裝與腳位 Package & pins | **3D** | 晶粒、凸塊、COG、COF、輸入/輸出 |

> 下列步驟為**教學骨架**,具體敘述在實作時依 §9 查證。`ext` = 延伸步驟,`deferred` = 保留不顯示。

### `basics` · 電與半導體
- 為什麼:後面所有零件都靠「用電壓控制電流」。
- 核心(3 步):① 電壓、電流、電阻(水管比喻:壓力差/流量/管徑)② 導體、絕緣體、半導體:半導體「可以被控制」③ 預告:用「電壓」當開關,去控制電流
- 延伸:④ 歐姆定律 V=IR(含公式) ⑤ 摻雜:N 型(多電子)、P 型(缺電子,稱電洞)⑥ PN 接面與空乏區 ⑦ 二極體:單向導通
- 互動:電壓/電阻滑桿看電流(核心);二極體偏壓(延伸,M3)。
- 常見誤解:電子沒有以光速移動;水管比喻的限度(不能解釋電場)。
- 模型:`sim/ohm`。

### `die` · 晶粒的層疊(3D)
- 為什麼:電路是「堆」出來的,不是平面畫的。
- 核心(6 步,**只用功能名稱**,不提前使用 `mosfet` 才定義的源極/汲極/閘極):① 剖面總覽 ② 最底下是矽基板 ③ 往上是「電晶體層」(開關住在這裡,下一章細講)④ 再往上是「配線層」,可有很多層,像道路與高架橋 ⑤ 層與層之間用連接孔(via)相通 ⑥ 最上面的接點(pad),之後會接到外面
- 延伸:閘極氧化層、接觸孔、絕緣層。
- 互動:逐層分離/合併;點層看名稱與作用。
- 常見誤解:層數與尺寸的量級;製程節點名稱(如「7 nm」)不是實際物理長度。

### `mosfet` · 電晶體
- 為什麼:邏輯與放大的最小單位。
- 核心(6 步):① 三個端點:閘極 G、源極 S、汲極 D ② 閘極 0 V:通道不存在,不通 ③ 閘極加壓:形成通道,電流通過 ④ 所以它是用電壓控制的開關 ⑤ 兩種相反的開關:一種閘極高電壓時通、另一種閘極低電壓時通;搭配 = CMOS,靜止幾乎不耗電 ⑥ 高壓版為何比較大
- 延伸:N 型/P 型與電洞(回扣 `basics` 延伸)、臨界電壓、基板端、較厚氧化層與間距。
- 互動:拖曳閘極電壓,看通道形成與電流。
- 常見誤解:「閘極有電流流過」(穩態幾乎沒有)。
- 簡化聲明:核心以功能描述 CMOS,不談 N/P 物理;須列入 `simplified[]`。
- 模型:`sim/mosfet`。

### `digital` · 數位與二進位
- 為什麼:電晶體只有「通/斷」,怎麼表示一個像素的亮度?
- 核心(5 步):① 開關有兩種狀態 ② 用高/低電壓代表 1/0,一個稱為位元(bit)③ 位元越多組合越多:2 位元 4 種、8 位元 256 種 ④ 8 位元 = 灰階 0~255:亮度的來源 ⑤ 類比(連續)與數位(離散)的差別;預告為什麼之後需要把數字變回電壓
- 延伸:二進位與十進位換算、為何電腦用二進位。
- 互動:8 個位元開關 → 顯示數值與對應的灰階方塊。
- 模型:`sim/binary`。

### `gates` · 邏輯閘到移位暫存器
- 為什麼:要把資料一格格送到上千條線,需要「記住並傳遞」。
- 核心(5 步):① 反相器(兩顆電晶體)② NAND 與真值表 ③ 正反器:在時脈的節拍記住 1 bit ④ 串成移位暫存器:每個時脈,資料前進一格 ⑤ 一列有幾千格,難道要打幾千下?(引出 `datapath` 的「鎖存」)
- 延伸:為什麼 NAND 是萬用積木、閘鎖如何用回授記住資料。
- 互動:點輸入開關即時看輸出;手動打時脈。
- 模型:`sim/logic`、`sim/shiftreg`。
- **MVP 做 ①②**。因 MVP 尚無 `digital` 章,① 先用一句話定義「0 = 低電壓、1 = 高電壓」;`digital` 完成後把定義搬到該章(只改 `introduces`)。

### `scan` · 面板如何掃描
- 為什麼:先懂面板的列與行,才知道驅動 IC 在忙什麼。
- 核心(6 步):① 像素排成格子,每格有一顆開關與儲存電容 ② **列驅動**(gate driver)一次選一列 ③ **資料驅動**(source driver)同時把整列的電壓送出 ④ 逐列掃完 = 一張畫面 ⑤ 更新率(Hz)= 每秒掃幾張 ⑥ 一列時間極短,所以驅動 IC 必須又快又同時
- **命名陷阱**:gate/source driver 的 gate、source 與電晶體的閘極、源極同名不同義。頁面一律用「列驅動」「資料驅動」,英文放括號,並在延伸說明由來。
- 互動:慢動作掃描、調更新率、調解析度看每列可用時間。
- 簡化聲明:OLED 像素為電流驅動、另有像素電路;以延伸卡片說明,不混入主線。
- 模型:`sim/scan`。

### `datapath` · 從資料到像素(主線高潮)
- 核心(7 步):① 介面傳輸與接收:資料變成一串高速的 0 和 1,用幾對導線傳到驅動 IC ② 灰階值(承 `digital`)由移位暫存器依序取樣一列 ③ 鎖存(latch)一次放出整列 ④ 電壓位準轉換(level shifter):把低電壓的訊號轉成高電壓的訊號 ⑤ DAC:數字變電壓,**對應不是一條直線** ⑥ 緩衝器(buffer)有力氣驅動長長的資料線 ⑦ 面板:像素電容充電,亮度出現(放大到一個像素)
- 延伸:伽瑪(gamma)曲線為何不是線性、電阻串如何做出 DAC、手機常見的 MIPI DSI 為例(差動、兩種模式、驅動 IC 有沒有影像記憶體)。
- 新名詞(核心 5 個):介面、鎖存、電壓位準轉換、DAC、緩衝器;**伽瑪已移到延伸**(核心只說「對應不是一條直線」)。
- 簡化聲明:省略時序控制、影像處理、電源產生等方塊;有些驅動 IC 內建影像記憶體、有些沒有,核心對應「主機持續送整張畫面」的情況。
- 說明:原本的「全流程總覽」步驟拿掉,由首頁的主線動畫擔任總覽。
- 互動:選灰階值 → 看對應電壓與亮度(核心);調伽瑪看曲線變化(延伸)。
- 常見誤解:亮度與電壓成正比。
- 模型:`sim/dac`、`sim/gamma`。

### `fab` · 製程與設計分工
- 核心(7 步):① 設計(邏輯 → 版圖)並做成光罩 ② 光刻:用光把圖案印在光阻上 ③ 蝕刻:把圖案刻進材料 ④ 摻雜:把少量雜質加進矽,改變導電性 ⑤ 沉積後堆疊下一層(重複)⑥ 切割成一顆顆晶粒並測試 ⑦ fabless:設計公司與晶圓代工的分工
- 延伸:光阻/曝光/顯影細節、研磨(CMP)、離子佈植。
- 注意:此章**不提凸塊**(留給 `package` 定義)。

### `package` · 封裝與腳位(3D)
- 核心(6 步):① 手機螢幕邊緣的位置 ② 一側是「輸入」少數接腳,另一側是「輸出」大量接腳 ③ 晶粒面朝下、金凸塊(gold bump)對準玻璃或軟板 ④ 兩種接法:玻璃上(COG)、軟板上(COF)⑤ 為什麼不用傳統塑膠封裝:要薄、邊框要窄、腳又多又細 ⑥ 回到整機
- 延伸:塑膠面板上(COP)。
- 待查證:腳數量級、腳距、各接法適用面板類型。

## 8. 視覺與動畫正確性(實作後的重點)

> 目標:IC 與相關物件的造型、動畫怎麼跑,都要「傳達正確」。這部分我與你都不是 IC 專家,**以審閱者審核為準**。

### 8.1 保真等級(每個視圖在 `docs/visual/<id>.md` 宣告)
| 等級 | 意義 | 使用 |
|---|---|---|
| L1 示意 | 關係正確,形狀與比例不論,圖上標「示意」 | 概念圖 |
| L2 結構 | 部件、順序、連接關係正確;比例標「非實際比例」 | **預設** |
| L3 比例 | 依真實比例,附比例尺與來源 | 僅在有可靠來源時才用 |

### 8.2 每個視圖的視覺規格(`docs/visual/<id>.md`)
元素清單與名稱、形狀依據與參考來源、顏色語意、**運動語意**(每個動畫對應哪一步的哪一句話)、簡化聲明、審核狀態(待審/已審/需修改)。**動畫不做純裝飾**(手繪抖動除外)。

### 8.3 先統一的易錯約定
1. **電流方向與電子移動方向相反**:動畫畫「電子」就依實際移動方向;畫「電流」依慣例方向;兩者同時出現時並列標示。頁面先固定只畫一種並加註。
2. **電洞是空位,不是會飛的粒子**:延伸章以「空位移動」表現。
3. **MOSFET 通道**:表現為「載子聚集形成通路」,不畫成機械閘門。
4. **資料移位**:每次移動與時脈同步顯示,預設慢動作,並標示速度。
5. **層疊剖面**:層順序固定(基板在下、配線在上);厚度不依真實比例,標「示意」。
6. **色彩語意固定**(電子、電洞、高壓、低壓、資料流各一色),且不只靠顏色。
7. **播放控制**:暫停、單步、調速(0.25×~2×)為每章標配。

### 8.4 審查流程
- `build` 為每個步驟輸出**關鍵畫格截圖**與**短影片**(開發審查用,不是產品功能,由 Playwright 錄製)。
- 審查表:名稱是否正確、形狀與順序是否正確、運動方向與速度是否合理、標籤是否清楚。
- 審閱者簽核寫入 `docs/review/<章 id>.md`;**未簽核的章在頁面顯示「待審」**。
- 3D 造型(`die`、`package`)先做低多邊形示意版,在 M1 逐項審,再細修。

## 10. 前端版面(清楚、整齊;桌機/筆電優先)

### 10.2 桌機/筆電(≥ 1024 px)

| 滑鼠 | 移上圖內標籤顯示說明;拖曳操作舞台 |

### 10.3 手機直向(< 700 px)降級
單欄:頂列 → 舞台(≥ 50% 高)→ 說明卡 → 步驟點 → 控制抽屜(預設收合,目標占畫面 ≤ 25%)。主線地圖收成 8 px 細線,點開展開。平板(700~1023 px)介於兩者。

### 10.4 設計代幣(CSS 變數,單一來源)
間距 4 的倍數;字級三階(說明 17、次要 14、圖內標籤 12 px;對比 ≥ 4.5:1);點擊目標滑鼠 ≥ 32 px、觸控(`pointer: coarse`)≥ 44 px;處理安全區;色彩語意固定;同類元件同一樣式;提供「降低動態」。

### 10.5 圖內標籤
統一「中文 English」;標籤不得重疊(排版演算法+測試);縮寫(如 COG)第一次出現旁附全名。

### 10.6 自動檢查(Playwright)
尺寸:1280×800、1920×1080、1024×768(主要);768×1024、414×800、360×740(降級)。檢查:無水平捲動;元件不重疊;點擊目標達標;文字不溢出;舞台比例與最小高度;鍵盤可操作(Tab 順序、焦點可見、快捷鍵);沒有只靠 hover 的資訊。

### 實作中發現並修正的問題
- 步驟被取消時,等待中的動畫永遠不會結束(單元測試抓到),已改為取消時丟出內部中止訊號。
- 1024 px 寬度出現橫向捲動:主線列在 grid 內撐寬頁面,已修。
- 平板寬度的心智圖節點只有 38 px 高:見上表第 3 點。
- 手機示意圖文字縮到約 4 px,我的第一個修正公式又把字放大到數百 px(e2e 當時沒有檢查圖內文字);已修,並補上第 4 點的檢查。
- 測試本身的副作用:對觸控視窗做整頁截圖會讓瀏覽器失去觸控模擬,後續檢查會誤判;截圖已改在獨立環境進行。

### 心智圖修正(RD 回饋:電晶體與主線 1~6 全部有關,不該掛在移位暫存器下)
- **問題**:我把「先修鏈」垂直畫在移位暫存器下面,讀起來像「所屬關係」;課程資料也與圖不一致(`mosfet` 只標了升壓與緩衝器)。這違反了 §6.3「流向與組成分開畫」。
- **修正**:課程資料新增 `foundation`(共同基礎)與 `hang`(掛在哪些主線零件下),每章必須恰好屬於「共同基礎 / 掛在零件下 / 晶片本身」其中一種。
  - 共同基礎層(`basics → mosfet → digital`)畫成一條橫跨主線 1~6 的底座,上方用 6 根支撐線對齊 1~6,**不含第 7 項(像素)**。
  - `gates` 掛在移位暫存器與鎖存之間;`datapath` 掛在 DAC;`scan` 掛在像素。
  - `mosfet.spine` 改為 1~6 全部;`digital` 為 接收、移位暫存器、鎖存、DAC;`gates` 為 移位暫存器、鎖存。
  - 先修連線只畫**直接先修**(傳遞約簡:`digital→datapath`、`mosfet→gates`、`die→package` 等冗餘線不畫),共 9 條。
- **測試**:單元測試檢查資料規則與約簡函式;e2e 以實際版面座標檢查「底座涵蓋 1~6 且不含 7、基礎章在底座內、各章對齊其主線零件、電晶體不是移位暫存器的子項、只畫 9 條直接先修線、章節頁高亮數量」。已用刻意破壞的版本驗證測試會報錯。
- **待 RD 確認**:像素(第 7 項)是否確實不含在「由電晶體組成」的範圍內(面板為薄膜電晶體,不在驅動 IC 內);介面接收是否算在共同基礎範圍內。

### 主線結構修正(RD 回饋:介面傳輸、面板)
- **主線**改為 `介面傳輸(IC 外)→ 1~6(驅動 IC 內)→ 面板(IC 外)`;原第 7 項「像素」改為「面板」(最後一幕仍放大到一個像素亮起)。兩端不編號、標「IC 外」,所以「1~6」的編號不變。
- **資料到像素章**(`datapath`)走過整條主線,不再掛在 DAC 下;地圖上從主線下方的**軌道**垂下(`span`)。`scan` 掛在面板下。
- **共同基礎層**與「驅動 IC」方框等寬,明確表示「驅動 IC 內的每個零件都由電晶體組成」;兩端在 IC 外,不在範圍內。
- **改名**:升壓 → **電壓位準轉換**(level shifter)。簡稱「位準轉換」。
- **內容編排**:介面傳輸併入 `datapath` 第 1 步,不另開新章(`introduces` 維持 5 個);伽瑪移到延伸。之後要加專章,只需新增節點並掛在「介面傳輸」下。
- **課程資料**新增:`SPINE[].zone`(source / ic / panel)、`short`(簡稱)、`NODES[].span`;每章恰好屬於 共同基礎 / 掛在零件下 / 整條主線 / 晶片本身 其中一種。
- **測試**:單元測試檢查主線結構、編號只有 1~6、各章位置;e2e 以實際座標檢查「IC 方框只包住 1~6、兩端在框外並標示 IC 外、共同基礎層與 IC 方框等寬、基礎章在層內、邏輯閘在移位暫存器與鎖存正下方、掃描章在面板正下方、有整條主線的軌道、只畫 9 條直接先修線」,以及新增的「標籤不得壓到文字」。已用刻意破壞的版本驗證會報錯。
- **介面標準(查證)**:手機驅動 IC 常見的是 MIPI DSI(實體層通常為 D-PHY):時脈通道加數條資料通道、每條為一對差動線;命令模式(驅動 IC 內有影像記憶體,只傳變動內容)與視訊模式(無記憶體,主機持續傳整張畫面)。**通道數量與速率各來源說法不一,不寫入教材**;MIPI 規格本文為會員限定,僅依公開二手資料,待審閱者確認。
- **待辦(下一步)**:首頁主線動畫 → 填入內容。

### 首頁主線動畫(M0,已實作)
- 一個資料封包沿主線下方的軌道由左到右移動,在**位準轉換**(變成較高電壓的位元)、**DAC**(變成類比電壓)、**緩衝器**(變得有力氣)三處改變形態,到面板後讓一個像素亮起。一輪 12 秒;原本規劃的「60 秒總覽」改為這個可循環的示意動畫,首頁的「60 秒總覽(準備中)」按鈕已移除,換成「暫停/播放動畫」。
- 時間軸為純函式(`app/flow.js`,有單元測試);畫面用 Web Animations API,**只動畫 transform 與 opacity**。可暫停;離開畫面自動暫停;「降低動態」時不播放、直接顯示亮起的像素;窄螢幕沿清單左側的線由上往下。
- 圖例(低電壓數位 / 較高電壓數位 / 類比 / 有力氣的電壓)與動畫使用同一份元素,形狀與顏色同時表達。
- 視覺規格:`ic-guide/docs/visual/home-overview.md`(待審)。
- **測試**:在固定時間點取樣(暫停並設定播放時間),檢查「各時間點應看到哪種封包」「封包不壓到方框、不出地圖」「到達時對應零件亮起」「像素在到達後才亮、下一輪前熄滅」「暫停/播放」「降低動態」「進度更新不重建地圖」「手機版沿清單移動」。
- **順帶發現並修正的問題**:首頁按 Esc 不會關閉學習面板與設定(Esc 只在章節頁有處理),已移到外殼;進度更新原本會整張重建地圖,現在只更新方框顏色,動畫不會被重置。
